================================================================================
          PROJECT MASTER PLAN & ARCHITECTURE SPECIFICATION
      Search-and-Rescue (SAR) Drone Companion Computer Subsystem
================================================================================

1. PROJECT OVERVIEW & STRATEGIC GOALS
--------------------------------------------------------------------------------
Project Name    : Project Aetheris (SAR Telemetry & Vision Companion Node)
Primary Languages: Rust (`no_std` compatible modules + async Tokio), C++20 (OpenCV)
Target Hardware : Raspberry Pi 4/5 or NVIDIA Jetson Orin Nano (ARM64)
System OS       : Linux (Embedded Ubuntu / Yocto)
License         : Dual MIT / Apache-2.0
Repository      : Public GitHub (Main Branch Protected)

Key Objectives:
1. Build a real-time, low-latency companion computer subsystem for drones that
   processes thermal/visual feed, detects high-heat targets (lost person / fire),
   and streams georeferenced tracking data to ground stations via MAVLink/CoT.
2. Achieve strict decouple between Computer Vision (C++) and Telemetry (Rust) 
   using high-performance POSIX Shared Memory IPC.
3. Enable 100% hardware-free development and integration using Synthetic Video
   datasets and ArduPilot/PX4 SITL (Software-In-The-Loop) simulation.


2. SYSTEM ARCHITECTURE & DATA FLOW
--------------------------------------------------------------------------------
[ Camera / Synthetic MP4 ] ---> [ C++ OpenCV Vision Engine ]
                                        |
                                        v (Writes at ~30 FPS)
                               [ POSIX Shared Memory ]
                                        |
                                        v (Reads at ~30 FPS)
[ SITL / Flight Controller ] -> [ Rust Telemetry Daemon ] -> [ UDP / LoRa Radio ]
  (MAVLink GPS Telemetry)               |                           |
                                        +----> [ Target Calc ] -----+
                                                  (Geo-mapping)

Data Pipeline Breakdown:
1. Vision Engine (C++): Captures frame -> applies Gaussian blur, thresholding,
   contour detection -> calculates target centroid -> writes to POSIX Shared Memory.
2. Telemetry Daemon (Rust): Connects to Flight Controller over UDP/Serial -> parses
   drone GPS (Lat, Lon, Alt, Heading) via MAVLink -> reads target centroid from SHM
   -> computes absolute target GPS -> packages & broadcasts MAVLink / CoT packets.


3. INTER-PROCESS COMMUNICATION (IPC) CONTRACT
--------------------------------------------------------------------------------
Shared Memory Identifier: `/sar_target_shm`
Semaphore / Lock Name   : `/sar_target_mutex`

6. GIT WORKFLOW & COLLABORATION GUIDELINES
--------------------------------------------------------------------------------
1. Branching Naming Convention:
   - `feature/vision-contour-detection` (Partner A)
   - `feature/rust-mavlink-parser` (Partner B)
   - `fix/shm-mutex-deadlock`

2. Commit Message Standard:
   - Use Conventional Commits standard:
     `feat(vision): add gaussian blur preprocessing step`
     `fix(telemetry): correct lat/lon integer scaling in mavlink packet`

3. Pull Request (PR) Policy:
   - No direct pushes to `main`.
   - Every PR requires at least 1 code review approval from the other partner.
   - All CI checks (automated compilation and tests) must pass before merging.


7. SIMULATION SETUP GUIDE (NO HARDWARE NEEDED)
--------------------------------------------------------------------------------
1. Video Feed Simulation (Partner A):
   - Download FLIR thermal dataset or thermal drone video sample (MP4 format).
   - Pass file path as command line argument to C++ executable:
     `./sar_vision_node --input ./assets/thermal_test.mp4`

2. Flight Telemetry Simulation (Partner B):
   - Install ArduPilot SITL / Docker container for SITL.
   - Run command: `sim_vehicle.py -v ArduCopter --console --map`
   - Connect Rust daemon to UDP port `14550`.
